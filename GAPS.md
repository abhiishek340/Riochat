# GAPS (repository level)

Decisions taken where the specifications are silent. Format:
`- <area> | <question> | <decision>`. Append only. Backend and web decisions are
in `backend/GAPS.md` and `web/GAPS.md`.

## docs and automation

- docs | Which documents does the repository carry? | `README.md`, `docs/{architecture,configuration,branding,api}.md`, and `.github/` with contributing guide, security policy, code of conduct, pull request template, three issue templates and two workflows. A root `NOTICE` exists; there is no LICENSE file because the owner decides licensing.
- docs/api | Should the docs list every route? | No. `docs/api.md` states conventions and area prefixes; the owning area's `Mount` is the source of truth for exact paths, so the page cannot drift from the code.
- ci | Spec describes a larger pipeline (image publishing, release tagging, code scanning, stale handling, dependency audit, Docker and Python jobs). | Implemented as `ci.yml` (change detection for backend, web, python and docker; Go build, vet, tests, gofmt; web typecheck, lint, tests, static build; ruff and the page-range tests for `deploy/services`; an unpushed image build with the GitHub layer cache; pull request commit-subject check), `docker.yml` (per-architecture image build on native runners, multi-architecture manifest lists, Docker Hub only when `DOCKERHUB_TOKEN` is set), `release-tag.yml`, `desktop.yml`, `desktop-channel.yml`, `codeql.yml` and `stale.yml`. Not implemented: the dependency-audit job (`pnpm audit`, `cargo audit`) and persisting the package store and Go caches between image builds (only the layer cache is kept).
- ci | Toolchain versions. | Go from `backend/go.mod`, pnpm from the `packageManager` field of `web/package.json`, Node 24 (the web package accepts 20.9 or newer).
- ci | Change detection. | A small `git diff` step in `ci.yml` marks the backend and web jobs; skipped jobs count as passing, so documentation-only changes do not run them. Pushes with no usable base commit run everything.
- ci | Spec calls for a reduced "sidecar" build profile. | Not applicable: the server has no build tags and always compiles every driver, so one build covers the desktop sidecar. The CI sidecar leg builds through `scripts/build-api.mjs --sidecar`, the same entry the local desktop commands use, so version, commit and build time are embedded identically.
- ci/desktop | Desktop release pipeline. | `desktop.yml` checks (version, fmt, clippy, lib tests with a placeholder sidecar), and on tags (or a manual run) builds macOS arm64, macOS x64, Linux x64 and Windows x64. On a tag one draft release is created first (more than one existing release for the tag fails the run) and `tauri-apps/tauri-action` uploads installers and the updater manifest into it; a final job renames the assets, reconciles `latest.json` and writes `SHA256SUMS` through `desktop/scripts/release-assets.mjs` and `checksums.mjs`; prerelease tags build with the beta updater endpoint through `release-config.mjs`; `desktop-channel.yml` runs `refresh-beta-manifest.mjs`; Linux legs run `prepare-appimage.mjs` first. Manual runs keep installers as `desktop-<leg>` workflow artifacts. Apple credentials are all-or-nothing (the certificate password may be empty); `APPLE_TEAM_ID` is also passed through because notarization with an Apple ID needs it. Not implemented: Windows certificate import and Authenticode verification, the WebView2 fixed-runtime offline zip, portable zips, provenance attestations, and the remote sign-and-notarize and DMG verification steps (local-only through `bundle:signed`). The Intel macOS runner label (`macos-15-intel`) should be confirmed when the workflow first runs.
- ci/desktop | Updater signing secret names. | `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, as the spec names them.
- github | Absolute URLs in issue template contact links. | They use `https://github.com/riochat/riochat/...`, matching the Go module path; change them if the repository lives elsewhere.
- github | Wording and categories of templates. | Original text; categories follow the spec's lists.
- docs/security | Response time promise in `SECURITY.md`. | "A few working days" for acknowledgement; no fixed fix deadline is promised.
- docs/branding | Branding is YAML-only. | Documented as such because the config loader reads it only from the file; changing it needs a restart. Colour accents are a build-time web concern (`globals.css`), not server configuration.

## build and deployment

- build/layout | Spec paths use `apps/web`; this tree has `web/`, `backend/`, `desktop/`. | The workspace members are `backend`, `web`, `desktop` and `packages/*` (none yet). The static export is `web/out`; the dev config template points `frontend_dist_dir` at `../web/out`. `make build-web` and the image use those paths.
- build/pnpm | Spec names pnpm 10.17.0. | `web/package.json` already pinned pnpm 11.22.0 and its workspace file used the pnpm 11 `allowBuilds` form, so the root pins 11.22.0 as well. The root `pnpm-workspace.yaml` carries the `allowBuilds` list (`@tailwindcss/oxide`, `esbuild`, `unrs-resolver`); `web/pnpm-workspace.yaml` and `web/pnpm-lock.yaml` were removed in favour of the root files. CI cache paths were repointed to the root `pnpm-lock.yaml`.
- build/workspace | The backend is Go but the spec lists "the backend's package manifest". | `backend/package.json` is a thin wrapper (`build`, `lint`, `typecheck`, `test` call the Go tools) so the task runner and `scripts/sync-version.mjs` treat it like any member. Shared JS libraries do not exist yet; `packages/*/package.json` is already covered by the version sync.
- build/turbo | Spec lists check/test/build as task names. | Turbo tasks are `lint`, `typecheck`, `test`, `build` and `dev`; the root `check` script runs `lint` and `typecheck` together and `verify` runs all four in one invocation. The backend build task is not cached (its output is outside the package).
- build/version | The API-documentation version annotation. | The backend has no Swagger annotations, so `backend/cmd/riochat/main.go` carries a `// @version x.y.z` line in its package comment; the sync tool rewrites it and fails when the line is missing. `desktop/src-tauri/tauri.conf.json` is synced when present and skipped while the shell has no configuration file yet. Drift is detected by comparing the canonical rewrite (2-space JSON, trailing newline), so a manifest with the right version but other formatting is reported as out of date.
- build/api-docs | `make api-docs` should regenerate Swagger docs and a TS contract. | The backend generates neither, so the target prints a notice and succeeds. Swagger UI, msgpack and OTLP exporter build tags do not exist either; there is a single build profile and the desktop sidecar uses the same binary (`scripts/build-api.mjs --sidecar`).
- build/catalog | Refreshing the bundled model catalog. | Added `backend/cmd/catalog-snapshot` (wraps `channel.EncodeCatalogSnapshot`; atomic write; non-zero exit and untouched file on any failure). The Dockerfile runs it when `REFRESH_CATALOG_SNAPSHOTS=true` and tolerates failure; `scripts/build-api.mjs` does the same for `RIOCHAT_REFRESH_CATALOG_SNAPSHOTS=1`.
- build/docker | SQLite C development library in the server build stage. | Not installed: the SQLite driver compiles its bundled C amalgamation, so only gcc (present in the Go image) is needed.
- build/docker | Unprivileged runtime. | The image runs as uid 10001 (`riochat`); `/app/data` and `/app/storage` are created and owned by that user before they become volumes. A bind-mounted `config.yaml` must be readable by that user. The spec does not mention a user; this is a hardening choice.
- build/docker | No `HEALTHCHECK` in the image or the app service. | The runtime image has no HTTP client and the server has no self-probe flag. Probe `/healthz` and `/readyz` from outside.
- build/docker | License files under `/app/licenses/Riochat/`. | The repository has no license grant yet, so only the root `NOTICE` is copied. Add the `LICENSE` copy once the owner adds one.
- build/docker | Demo credentials of the full profile. | PostgreSQL `riochat-demo-password`, Redis `riochat-demo-redis`, overridable with `RIOCHAT_POSTGRES_PASSWORD` and `RIOCHAT_REDIS_PASSWORD`; documented as replace-before-production. The Redis health check passes the password through `REDISCLI_AUTH`.
- build/config | Container and dev templates use `app.env: dev`. | Templates ship the built-in placeholder secrets, which the server accepts only in dev and warns about. They run unchanged on loopback; `deploy/README.md` lists what to change for prod (secrets, https public URLs, CORS, SSRF protection). The default template keeps the dev `frontend_dist_dir`; the image sets `FRONTEND_DIST_DIR`, which wins over the file. `backend/internal/platform/config/deploy_templates_test.go` loads all three templates, rejects unknown keys and checks that prod refuses their placeholders.
- build/config | Spec's default for `server.trusted_proxies` (loopback, RFC1918, IPv6 loopback and ULA) differs from the loader's empty default. | The templates list those ranges explicitly.
- build/config | Relative storage and data paths in the dev template. | They resolve against `deploy/` (the loader's rule) to `.local/` at the repository root, which is git-ignored.
- build/desktop | Development identifier and data separation. | `desktop/scripts/dev.mjs` passes `src-tauri/tauri.dev.conf.json` (identifier `com.riochat.desktop.dev`, product `Riochat Dev`), which moves app data and credential entries away from release builds. `bundle:fast` builds the app bundle only with thin LTO, 16 codegen units and opt-level 2, and switches updater artifacts off when no updater private key is in the environment. (An earlier `desktop/scripts/tauri.mjs` duplicated these entry points with different behaviour and was removed.)
- build/desktop | Local signed release. | `make release-desktop` calls `desktop/scripts/build-signed.mjs` (the former `scripts/desktop-release.sh` was removed because it skipped the DMG re-encoding, the signing-service path and the bundle verifier). It has not been run against real certificates.
- build/windows | Separator of `ProxyBypassList` entries. | Not specified; the `.reg` example uses `;` in a commented sample. Confirm against the desktop shell's parser.
- build/windows | ADMX policy shape. | One category, `DefaultServerUrl` (text), `LockServerUrl`, `DisableLocalMode`, `DisableAutoUpdate` (boolean, 1 or 0) and `ProxySettings` (enum plus two text elements), all class Both under `SOFTWARE\Policies\Riochat`, supported on Windows 10 or later. `.gitattributes` forces CRLF for `.reg`, `.admx` and `.adml`.
- build/services | Optional extraction services (spec section 7). | `deploy/services/{rapidocr,tesseract,docling,tika}`, each with its own compose file attaching to the external `riochat-network`, loopback-only ports 8002, 8004, 8005 and 9998. The backend's OCR client posts the page selection in a form field named `pages` while the spec names it `page_ranges`; both Python OCR services accept either. The page-range parser is duplicated in the two paginating services so each stays a self-contained build context; `ruff.toml` at the root configures lint and format for them. The Docling image downloads its models on first use into the `riochat-docling-models` volume.
- build/dev | `make desktop` and `make build-desktop` need a web client. | The dev configuration's `beforeDevCommand` (`scripts/dev-server.mjs`) reuses a web dev server answering on port 3000 or starts one; `tauri build` needs `web/out` to exist (`make build-web`); `make release-desktop` always rebuilds the web export, then runs `bundle:signed` when `deploy/secrets/desktop-signing.env` exists and `bundle` otherwise.
- build/web-image | Lint findings in the image build. | `next build` runs ESLint by default, so any style finding stopped the image and the desktop export. `web/next.config.ts` sets `eslint.ignoreDuringBuilds`; lint stays a separate gate (`pnpm lint`, CI `web` job). Type errors still fail the build. Two existing lint violations in the web sources were also fixed.
- docs/review | Sidecar file name. | Spec section 5 names the bundled program `riochat-server`; the sidecar build output, the dev wrapper, `desktop.yml` and the Tauri `externalBin` entry all use `desktop/src-tauri/binaries/riochat-server-<target triple>[.exe]` (supersedes the shorter name in the `ci/desktop` entry above).
- docs/review | Rotation wording. | The encryption key ring decrypts with retired keys, but no background job re-encrypts stored values and no `data_encryption_key_rotation_completed` event exists, so the docs and templates tell operators to keep the old key listed.
- docs/review | GeoIP and tracing are wired. | The platform-llm area builds the GeoIP resolver (`ipwhois`, `ipinfo`, `mmdb`, or off with `none`) and an OTLP/HTTP JSON trace exporter; docs describe them as working, with the gRPC protocol value falling back to HTTP.
- docs/review | SSRF switch scope. | The outbound policy is enforced only when `APP_ENV=prod` and `SSRF_PROTECTION_ENABLED` is on; documented as is.
- docs/review | Rate limits. | They ship disabled (`auth.rate_limit_enabled=false`); the API page states the base budgets that apply once enabled instead of presenting them as defaults.
- docs/review | Desktop crate license. | No license is declared in `Cargo.toml` or `tauri.conf.json`; `package.json` says `UNLICENSED`. The owner chooses the terms.
- ci | Repository checks job. | `ci.yml` gained an always-on `repo` job (version manifests against `VERSION`, Node tests of `scripts/`), and the shared-input pattern for change detection now includes the root workspace files and `scripts/`. Docker image build and publishing jobs are still not wired (the Dockerfile exists, but nothing here could run Docker).

## desktop

- desktop/sidecar | The spec builds the server from `./cmd/server`; this tree's entry point is `backend/cmd/riochat`. | `scripts/build-sidecar.mjs` builds `./cmd/riochat` and still names the output `riochat-server-<triple>[.exe]`, the external-binary name the spec fixes. The Tauri `externalBin` entry is `binaries/riochat-server`.
- desktop/sidecar | The spec's build tags (`nopostgres,noredis,...`). | Passed as specified; this backend defines no such tags, so they are harmless today and become effective if the backend adds them.
- desktop/sidecar | The model-catalog refresh tool named by `RIOCHAT_REFRESH_CATALOG_SNAPSHOTS=1` does not exist in the backend. | The script runs `go run ./cmd/catalog-snapshot` only when that folder exists and otherwise prints a note; a failed refresh never fails the build.
- desktop/sidecar | The sidecar must target the bundle's minimum macOS (12.0). | The script passes `-mmacosx-version-min` and `MACOSX_DEPLOYMENT_TARGET` to cgo. Go itself also sets a floor: Go 1.27 emits macOS 13 objects (the linker warns), so a release build must use the Go release named in `backend/go.mod` (1.26). `verify-macos-bundle.mjs` fails a bundle whose binaries declare a newer minimum.
- desktop/sidecar | The spec does not say how stdout lines arrive. | The shell plugin delivers one event per line; each is trimmed and parsed as JSON. Standard input stays open while the shell runs, so the server's "exit when stdin closes" rule also covers a crashed shell.
- desktop/web-contract | The spec says the page detects the shell through the Tauri global; the web client in this tree reads `window.__RIOCHAT_DESKTOP__ === true`. | Every webview gets the initialization script `window.__RIOCHAT_DESKTOP__ = true;` (the Tauri globals are present as well).
- desktop/web-contract | The strip page `/desktop/tabs`. | The web client now builds it (`web/src/features/auth-shell-share/desktop/strip.tsx`; see `web/GAPS.md`). The web client listens to `downloads:finished` and checks for updates through `check_update`, matching the shell.
- desktop/web-contract | `set_network_proxy` is documented as `{ settings, password? }`. | Registered as two named arguments, `settings` and `password`, which is what `invoke("set_network_proxy", { settings, password })` sends. `tabs_activate(id, focus)` treats a missing `focus` as true.
- desktop/updates | The web client calls the JavaScript updater plugin (`plugin:updater|check`) directly; that plugin cannot use the shell's proxy route. | `check_update` (route-aware, stores the update by `rid`) and `check_update_notice` are implemented as specified for the web layer to use. The plugin permission set is granted at runtime in `auto` mode only; if granting fails the app still starts and only loses installation.
- desktop/updates | The signing key embedded in `tauri.conf.json` is a public key only. | It is a syntactically valid minisign public key whose private half was discarded, so no update can verify until the release key replaces it: run `tauri signer generate`, keep the private key in `TAURI_SIGNING_PRIVATE_KEY`, and put the new public key in `plugins.updater.pubkey`.
- desktop/capabilities | The spec says tabs get notification "show and permission query". | Tabs get `notify`, `show`, `is-permission-granted`, `permission-state` and `request-permission` (the notification shim cannot ask the user without the last one). The strip gets the two query permissions. `process:allow-restart` is granted instead of the whole process default set, so a page cannot call `exit`.
- desktop/oauth | "Serves exactly one request" for the loopback listener. | The listener answers invalid requests (400/404) and keeps waiting; only a valid callback, replacement, cancellation or the 600 s limit ends it. One stray probe (for example a favicon fetch) therefore cannot break a sign-in.
- desktop/oauth | The mark in the response page. | An inline SVG drawn from the same geometry as the application icon, embedded as light and dark data URIs.
- desktop/proxy | Credentials in `HTTP_PROXY`-style environment variables. | They are accepted (percent-decoded) and used for shell requests and written back percent-encoded to the sidecar. Credentials remain rejected in policy and manual addresses.
- desktop/proxy | macOS system proxies are read from the "dynamic store". | The shell parses `scutil --proxy` output instead of linking SystemConfiguration. Windows reads `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` (WPAD auto-detect alone is not reported as PAC).
- desktop/proxy | Bypass entries with a trailing dot or IPv6 brackets. | `[v6]` and `[v6]:port` are kept; everything else follows the spec's character rules.
- desktop/proxy | The update check needs a bypass decision for `github.com`. | The first updater endpoint is matched against the effective bypass list; a hit means a direct connection.
- desktop/proxy | `hasPassword` versus "password read only when manual with a user name". | The keychain is read for the presence check whenever a user name is saved (any mode); the password is used only for a manual proxy.
- desktop/window | Linux strip height and macOS title-band dragging. | Bounds are set explicitly for every webview on every resize; no extra GTK handling is added. The title band is covered by the strip webview, so no native band dragging is configured.
- desktop/window | The macOS Cmd+Shift+W patch and compact toolbar use `objc2` calls on the installed AppKit objects. | The patch rewrites the native item whose modifier mask contains Shift to key equivalent `W` with Command only; both pieces are compiled and the app starts, but the key behaviour could not be exercised without a user.
- desktop/portable | Instance-id creation race. | `create_new` then write; a losing starter polls briefly for the winner's content and replaces the file only if it stays invalid. Hard links are not used because portable media is often exFAT.
- desktop/portable | WebView2 access rights for a bundled runtime. | `icacls` grants read/execute to `*S-1-15-2-1` (ALL APPLICATION PACKAGES) and `*S-1-15-2-2` (ALL RESTRICTED APPLICATION PACKAGES), once per folder, recorded in `.riochat-acl-granted`.
- desktop/windows | Code that only compiles on Windows (registry readers, message boxes, WebView2 arguments). | Built and tested logic is platform-neutral; the Windows-only glue was checked with `cargo check` of the same snippets for `x86_64-pc-windows-msvc` in isolation, not as a full crate build.
- desktop/release | Names of the four signing-service variables and the service protocol. | Variables are `SIGN_AND_NOTARIZE_{SCRIPT_URL,BASE_URL,API_TOKEN,HELPER_URL}` (as in `deploy/secrets/desktop-signing.env.example`). The downloaded script is run as `bash script app <path> --release <name>` and `bash script dmg <file> --release <name>` with the other three values in its environment. This protocol is this repository's own choice.
- desktop/release | AppImage wrapper. | `prepare-appimage.mjs` replaces the cached linuxdeploy with a shell wrapper that passes `--exclude-library` for the four Wayland libraries and exports itself as `LINUXDEPLOY` for the GTK and GStreamer plugins. The tool download URLs are the upstream release locations and are not pinned by checksum.
- desktop/release | Asset names for rpm and AppImage updater files. | `Riochat-<v>-<rel>.<arch>.rpm`, `Riochat_<v>_<arch>.AppImage`/`.deb` and their `.sig` files map to `Riochat-<v>-linux-<arch>.<ext>`; other bundler shapes are left alone.
- desktop/ci | Sidecar file names in `desktop.yml`. | The workflow creates the placeholder as `riochat-server-<triple>` and builds the real one with `node scripts/build-api.mjs --sidecar`, which writes the same name.
