# GAPS

Decisions taken where the specs were silent or left a choice open.
Format: `- <area> | <question> | <decision>`. Append only.

- web/api-base | The spec makes a loopback page on a port other than 8080 call `http://<host>:8080` directly. | Dropped: the dev server proxies `/api/*`, so the default is always same origin; only `NEXT_PUBLIC_API_BASE_URL` or a runtime override changes it. Avoids cross-origin cookies and CORS in dev.
- web/dev | The backend rejects any `Origin` outside its CORS allow-list, and the proxy forwards the browser's. | Documented that dev needs `CORS_ALLOW_ORIGIN=http://localhost:3000` on the backend; the web app does not rewrite headers.
- web/i18n | Spec substitutes the brand name in six named messages after load. | Every message gets an implicit `{brand}` argument instead; catalogs use `{brand}` wherever the product name appears.
- web/i18n | Library choice. | Own provider and ICU-subset formatter (plural, select) rather than next-intl, since locales are cookie-based and the site is a static export. Catalogs are split per namespace under `lib/i18n/catalog/<locale>/`.
- web/i18n | Where do feature namespaces go? | Each area adds `<ns>.ts` to both locale folders plus one index line; parity is checked by types and by `pnpm test`.
- web/theme | Spec names eight presets of the original look. | Original design: four accent presets (`tide` default, `ember`, `moss`, `dusk`) on shared neutrals; attribute is `data-accent`, storage keys stay `theme` and `theme-preset` for per-device compatibility.
- web/theme | Appearance preferences (chat font, font-size scale) are specified. | Deferred to the settings/appearance feature; the foundation ships only mode + accent.
- web/theme | Spec disables user zoom in the viewport. | Zoom stays enabled (accessibility); no maximum-scale.
- web/fonts | Bundled UI fonts. | System font stacks (with CJK fallbacks) so the build needs no network or font files.
- web/branding | Default favicon path. | Static default is `/icon.svg`; `/favicon.ico` and `/riochat-icon.svg` also ship because the backend's default branding names them.
- web/branding | Legacy service-worker migration (tombstone `sw.js`). | Not implemented: a fresh deployment has no legacy worker.
- web/pwa | Manifest source. | Linked to the backend's dynamic manifest endpoint rather than a static file, so branding changes apply.
- web/auth | Session-ending 401 on the first attempt (spec 1.1 says nothing is retried, 1.2 only skips retry for class `other`). | Followed 1.1: the session is cleared (if no newer session appeared) and the error is rethrown without refresh.
- web/auth | `refresh()` without a failed token while a token is stored. | Always performs the transport call; the "adopt the stored token" shortcut applies only when a failed token is given.
- web/auth | Login page scope. | A minimal password + second-factor form lives in `features/auth` so the foundation is testable end to end; registration, reset, providers and onboarding are the auth feature's job.
- web/stream | Wire formats. | Generation streams are consumed as back-to-back JSON documents (NDJSON, matching the backend); the active-run feed as SSE through fetch so the bearer header works. Callers may pass `Accept: application/x-ndjson`.
- web/shell | Sidebar hover-reveal of the icon rail and the lock API. | Not implemented; the rail shows icon tooltips instead. Collapse/restore thresholds (1180/1360 px), persistence and Ctrl/Cmd+B follow the spec.
- web/shell | Header actions for pages. | Pages portal into the header with `<HeaderActions>`; title overridable with `usePageTitle`.
- web/shell | Onboarding overlay, announcements dialog, desktop notifiers. | Left to their features; the shell has no slots for them yet.
- web/app-version | Comparing the running bundle with the server build. | The bundle has no id of its own; the guard remembers the first build id the server reported and prompts a reload when a later check (on focus, at most per minute) differs.
- web/routes | `/preview/image-loading`. | Created by the chat work, see the web/chat routes entry. `/desktop/tabs` now exists, see the web/desktop entry on the tab strip.
- web/routes | Static export has no dynamic segments. | `/share` takes the id from the query string (as the spec's route table says); keep that style for any new detail pages.
- web/ui | Component coverage versus the spec's long list (calendar, command palette, drawer, ...). | The foundation ships button, input/textarea/select, field helpers, dialog + confirm dialog, dropdown menu, tooltip, toast (six positions, store usable outside React), table, tabs, switch, card, badge, skeleton, spinner, empty state. Others are added by the first feature that needs them, in `components/ui`.
- web/tooling | Package manager scripts policy. | `pnpm-workspace.yaml` allow-lists the install scripts of `@tailwindcss/oxide`, `esbuild`, `unrs-resolver`; otherwise pnpm 11 fails `install` with `ERR_PNPM_IGNORED_BUILDS`.
- web/files | Deep link `?file=` is meant to be found "by searching for its ID", but the backend `q` only matches file names. | `locateFile` asks with the ID first, then walks the plain list (created order, up to 10 pages of 100) until it finds the file; if it never turns up, selection falls back to the first item.
- web/files | Viewers the spec names (docx, Office documents, code highlighting, media zoom/fullscreen, rendered markdown through the shared renderer). | No document-conversion library ships with the client. docx and native Office files show a "download it" message instead of a viewer; code and plain text use a monospace block (no syntax colouring); markdown uses a small built-in reader (headings, lists, quotes, fences, emphasis, links); CSV renders as a table (first 500 rows); images get zoom in/out/reset; audio/video use the browser controls.
- web/files | PDF preview. | Rendered by the browser's own viewer in an iframe on the blob URL.
- web/files | "Select all" / "Cancel" wording and the marquee for long names. | Button reads "Select all" / "Clear selection"; long names truncate with the full name in the `title` tooltip instead of scrolling.
- web/files | Thumbnail for image files. | Uses the preview's blob URL once it is ready, otherwise the type icon with a two-letter fallback.
- web/files | Upload merge when sorting is not "newest first". | A new item is always inserted at the top and the background reload then puts it where the server sorts it.
- web/files | Success toast when some uploads failed. | Only the "Some uploads failed" error toast is shown (as in the spec's scenario 6); successes are visible in the list.
- web/files | Info drawer. | Implemented as a centred dialog titled "File details" (same fields, same conditional rows).
- web/files | Cross-tab invalidation transport. | Window event (same tab), BroadcastChannel, and a localStorage write observed through `storage` events; subscribers de-duplicate by nonce (last 50). Exposed to other areas as `announceFilesChanged` from `@/features/files-kb-library`.
- web/kb | Where the admin console gets its knowledge-base screen. | `KnowledgeBaseWorkspace mode="admin"` is exported from the files-kb-library index; `/admin/knowledge-bases` (admin area) can render it directly. It does not re-check the feature policy in admin mode.
- web/kb | Cross-tab invalidation for knowledge bases. | A localStorage write (`riochat:knowledge-bases-changed`) observed through `storage` events in other tabs; also refreshes on window focus and tab visibility (throttled to 250 ms).
- web/kb | Sidebar "Edit" for a base that is not selected. | Opening the editor also selects that base (spec 2.8).
- web/kb | Bulk delete sends `delete_files=true` only for bases that actually contain files, even when the option is ticked for the batch. | Avoids requiring the file-delete capability for empty bases (the backend only needs it when the flag is present).
- web/kb | Admin-mode upload endpoint response. | Only `file.fileID` is used from `POST /admin/knowledge-bases/files`.
- web/library | Opening a skill from a list summary (no SKILL.md body). | The full object is fetched with `GET /skills/{id}` before the edit or view dialog opens, for own skills as well as built-in ones; a failure shows the load-failed toast and nothing opens.
- web/library | Native form validation in the item dialog. | Disabled (`noValidate`) so the localized "Enter a name and ..." toast is what the user sees.
- web/library | Skills list beyond 100 items. | Only page 1 (100 items) of each skills source is read, as specified; prompts page through everything.
- web/tests | Component tests in vitest. | `vitest.config.ts` gained `esbuild.jsx = "automatic"`; test files opt into jsdom with a `// @vitest-environment jsdom` docblock and mock the i18n provider with the real en-US messages.
- web/ui | Menu rows that toggle. | `components/ui/dropdown-menu-checkbox-item.tsx` adds `DropdownMenuCheckboxItem` (not re-exported from the barrel to avoid touching it).
- web/auth-shell-share/layout | The location of the area's code and routes. | All of it lives in `features/auth-shell-share` (auth, onboarding, share, recent, shell, desktop, lib); the placeholder features `auth`, `share` and `recent` were removed and their routes (`/login`, `/auth/callback`, `/share`, `/recent`) now import from the new index. `/desktop/setup` is new.
- web/auth | Login-page marketing panel and animated backdrop (spec 1.12). | Not built: the card inside the shell's `AuthLayoutFrame` is the whole page, with an original headline and a collapse/fade-in once the server options arrive.
- web/auth | Which client ids does the provider bridge expect? | `riochat-web` in browsers and `com.riochat.desktop` in the desktop shell, as the backend validates (`com.riochat.native` is for mobile and unused).
- web/auth | How is an expired second-factor challenge recognised? | By HTTP 401 plus either the message `two factor challenge expired` or the backend code `auth.two_factor_expired`.
- web/auth | Backend login rejects usernames shorter than 3 characters and passwords shorter than 6. | The form sends whatever was typed (trimmed account); the server message is shown. The client-side password policy (8-128, not digits only) is applied only to registration, reset and the bootstrap password, as in the spec.
- web/auth | Desktop in local mode has no login form. | The login page shows a "starting" status (with Retry on failure) while the shell mints the local session; the "Register in browser" link opens `<api base>/login`.
- web/auth | Turnstile widget source. | Loaded on demand from `challenges.cloudflare.com` only when registration needs it; failure to load leaves the token empty so submit stays disabled.
- web/onboarding | Spec lists eight theme presets and an AI-vendor logo carousel. | Four original accent presets (the foundation's) are offered; the account bundle written to `appearancePreferences` always carries all four keys (`preset`, `chatFont`, `chatFontWeight`, `fontSize`), keeping existing values. The logo carousel is replaced by thirteen original rotating tips (8 admin, 5 user, every 4.2 s).
- web/onboarding | Going back from the theme step to the two-factor step after skipping. | Skipping cancels the server-side setup; returning to step 3 enrols afresh (once). Step 3 itself has no back button.
- web/onboarding | When does the overlay close while recovery codes are showing? | It stays mounted (even if the profile stops reporting `initialSecurityRequired`) until the last step is finished.
- web/onboarding | Timezone list. | `Intl.supportedValuesOf("timeZone")` with a short built-in fallback; the personalization step only sends the zone (appearance was already saved in step 4).
- web/share | Artifact side panel and interactive UI blocks on the share page. | Not available in the foundation: messages render through a small built-in Markdown subset (`lib/mini-markdown.tsx`, elements only, no raw HTML, http(s)/mailto/same-origin links); fenced `riochat-ui` blocks therefore show as plain code even when `uiComponentsEnabled` is true.
- web/share | Sidebar collapsed by default in the share wrapper. | Not implemented: `SidebarProvider` is shared and keeps the user's own preference. The wrapper mounts nothing until the session question is answered, so the page never remounts.
- web/share | Copy link origin. | Share links use `publicWebOrigin(apiBase)` (the page origin in browsers, the server address on desktop).
- web/shell | Sidebar Projects / Starred / Recent sections, the project dialog, drag-reorder and the conversation row menu (spec 3.4-3.15). | Owned by the chat feature's `ConversationSidebar` slot because it owns the conversation store. This area provides the pieces around it: global search, shortcuts, user-menu items, announcements, onboarding, desktop notifiers and a window-event bus (`announceConversationChange` / `subscribeConversationChanges`, event `riochat:conversation-changed`) that lists without a shared store use to stay in step.
- web/shell | Where do the search entry and "New chat" shortcut live? | A search button sits in the shell header (the nav list only holds links); Ctrl/Cmd+K opens it and Ctrl/Cmd+Shift+O dispatches `riochat:new-chat` and routes to bare `/chat`. Chat should listen for the event to reset its view.
- web/shell | Search dialog default list and the "all starred" variant. | With no shared sidebar store the empty-query list is fetched (page 1) and cached for 30 s; the local-filter variant for starred conversations is not built.
- web/shell | Build-staleness check (spec 3.7) versus the foundation's simpler guard. | `AppVersionGuard` now follows the spec: skipped on desktop, first check on mount, then every 10 minutes and on focus/visibility, non-initial checks throttled to one per 10 minutes and never overlapping, one persistent toast with a fixed id.
- web/shell | User menu additions. | Settings now links to `/settings/general`; Announcements (dot for unread), Language submenu (persisted best effort with `PATCH /me {locale}`), Upgrade plan (billing gating) and the desktop download link were added. A blank `desktopDownloadURL` hides the download entry (no invented fallback address). Sign-out ignores repeat clicks and shows a progress label.
- web/announcements | Backend returns a bare array and has no unread-only filter beyond `include_dismissed`. | Unread means `closedAt` is empty. "Not again today" and "Close" both mark the handled items read in the local list on success; the dialog stays open and shows a toast if any request fails.
- web/recent | Backend verbs differ from the spec's wording. | Used the real routes: `PATCH /conversations/:id/star {starred}`, `PATCH .../archive {archived}`, `PATCH .../project {projectID}`, `POST /conversations/project {conversationPublicIDs, projectID}` -> `{updated}`, `POST /conversations/shares/revoke`, `GET /conversations/export` (manifest line has `_type: "export_manifest"`).
- web/recent | Project filter UI. | The filter comes from `?project=`; a removable chip shows it. No project dropdown was added to the toolbar.
- web/recent | Live store events. | Replaced by the window event bus described above; the page also announces its own changes on it.
- web/recent | New chat from this page. | Dispatches `riochat:new-chat` and routes to `/chat?project_id=<id>` (or `/chat`); creating the conversation is chat's job.
- web/desktop | Network-proxy settings tab and distribution line on the About page. | Not part of this slice (proxy settings belong to the settings area; `loadDistribution()` is available in `features/auth-shell-share/desktop/distribution.ts`).
- web/desktop | The tab strip page `/desktop/tabs`. | `desktop/strip.tsx` (pure helpers and its own English/Chinese strings in `strip-model.ts`). `RootProviders` renders that one route without branding, i18n, session or guard providers, as the shell spec asks; the strip lifts the branding veil itself. It calls `tabs_list`, `tabs_open`, `tabs_activate(id, focus)`, `tabs_close`, `tabs_move` and listens to `tabs:changed`. Pressing a tab activates it with `focus=false` (moving focus would cancel a drag); releasing without a drag activates with focus. Window buttons (Windows only) call `plugin:window|minimize`, `toggle_maximize` and `close`; the macOS strip leaves 78 px for the traffic lights; the drag region is `data-tauri-drag-region`.
- web/desktop | Talking to the shell without `@tauri-apps/api`. | `desktop/bridge.ts` calls `window.__TAURI_INTERNALS__.invoke` directly (commands `get_server`, `set_remote_server`, `set_local_server`, `leave_server`, `store_session`, `clear_session`, `refresh_session`, `local_sign_in`, `start_oauth_loopback`, `stop_oauth_loopback`, `get_distribution`, `check_update_notice`; plugin commands `plugin:updater|check`, `plugin:updater|download_and_install`, `plugin:process|restart`, `plugin:opener|open_url`, `plugin:event|listen`). The download event is `downloads:finished` (payload `{fileName, success}`), as the shell emits it. Update checks go through the shell's `check_update` command (proxy-aware, keeps the update by `rid`); `plugin:updater|download_and_install` then installs it.
- web/desktop | How does the web client learn the bound server and refresh sessions? | `DesktopGate` (mounted in the root providers) asks the shell, sets the API base override, registers a native refresh (`registerNativeRefresh` in `refresh-transport.ts`) and a sign-out cleanup; in local mode signing out leaves the server so the setup screen returns.
- web/files | What the list shows when the first page fails to load (the spec only names a toast). | An error empty state with a "Try again" button replaces the empty-library message (so a failure is never read as "no files"); the same applies to the knowledge-base list, a base's file list, the add-sources list and both library tabs.
- web/files | A failed next-page load during infinite scroll. | Automatic paging stops after one failure; the footer shows an inline message with "Try again" (an explicit retry is the only thing that resumes it), so a persistent failure cannot loop.
- web/files | "Open" and "Download" for files a browser would run as a page (HTML, SVG, XML, scripts). | A blob URL inherits the app's origin, so for those content types the preview still renders from the typed blob (an SVG stays an image) but Open/Download use a text/plain copy of the bytes.
- web/kb | `processing` flag after a local "queued" mark. | Knowledge-base file payloads carry the server's `processing` flag, which wins over status words in the polling rule; marking a file queued therefore also raises that flag when the payload has one (library files have none and are not given one).
- web/kb | Add-sources dialog keyboard model. | A plain list: the row checkbox is the keyboard control (Space natively, Enter added); clicking the row also toggles. No listbox/option roles, because rows hold a checkbox and a delete button.
- web/library | Length limits count characters the way the server does (code points), not UTF-16 units, so 64 emoji are accepted.
- web/files | CSV viewer. | The first row is rendered as a column header row (th scope=col).
- web/settings routes | The task lists skills, MCP and memory pages that the spec's section table does not have. | Added `/settings/memory` (all three memory scopes), `/settings/skills` (own skills plus read-only built-ins) and `/settings/tools` (default MCP tool selection) between Chat and Models; the nav order is General, Chat, Memory, Skills, Tools, Models, Plan & usage, Account, Network, About. Route guards and the "wait for capabilities" rules are unchanged.
- web/settings appearance | The account stores preset names from the server's fixed list (default, azure, cobalt, graphite, lagoon, ink, ochre, sepia) but the web app has four accents. | Each accent writes one server name (tide=azure, ember=ochre, moss=lagoon, dusk=ink); every server name reads back as some accent (default/cobalt -> tide, graphite -> dusk, sepia -> ember). Round trips of the four accents are lossless.
- web/settings appearance | Font size and reply font/weight have storage keys and `data-*` attributes but no styles were specified. | `globals.css` scales `html` font-size (88/112/124 %) for the three non-default sizes and exposes `--chat-font-family` / `--chat-font-weight` plus a `.rio-reply` utility for the chat view. The theme bootstrap script also applies the three attributes before first paint.
- web/settings runtime | Where the font provider and the account-to-device sync mount. | `AppearanceRuntime` (exported from the settings index) is loaded with `next/dynamic` (no SSR) from `RootProviders`, so the settings feature is not part of every route's first chunk.
- web/settings avatar | "Generated" avatars (`generated:github:<n>`) need a renderer. | Original deterministic 5x5 mirrored pattern on a two-hue gradient seeded by `n`; the reference format is unchanged. Uploaded avatars of other users are read from `GET /users/<publicID>/avatar?v=<updatedAt>`.
- web/settings avatar | The upload response shape. | The file id is read from `fileID`, `id` (when it starts with `file_`) or the same fields of a nested `file` object.
- web/settings models | The built-in icon catalog and well-known providers are not listed. | A catalog of 34 neutral glyph icons (slug stored; empty = automatic) and a small table of well-known API hosts (OpenAI, Anthropic, Google AI, xAI, OpenRouter, DeepSeek, Mistral, Groq, Together, Moonshot, DashScope) that picks a default protocol, name and icon.
- web/settings models | The model picker uses a popover-less layout. | It is a dialog on top of the add/edit dialog; the icon picker is an inline panel under its button (the UI kit has no popover).
- web/settings models | Where a probe result is kept when the picker is cancelled. | The probe and the pre-selection (catalogs of 12 or fewer) stay in the add dialog; cancelling the picker discards only that session's ticks. Changing the address or key discards both.
- web/settings import | Desktop shells and `AuthGuard`. | `/import` wraps its signed-in content in the shared `AuthGuard` after scrubbing and stashing the fragment (session storage key `riochat:import-link`, 10 min). The stash is cleared as soon as any non-loading screen shows.
- web/settings import | Batch rows after the free slots run out. | Rows that are not imported show "over limit" as soon as no slot is left, as in a run that skipped them; a row waiting in "needs selection" can still be completed through the add dialog.
- web/settings billing | "Rows beyond 100 are virtualized" in the usage log. | The page size options stop at 100, so a page never exceeds 100 rows and no virtualization is needed.
- web/settings billing | Which cell shows what in the usage log. | "Model cost" is the entry's own billed amount minus its service items; "Service cost" sums its own service items and the service-only entries folded into it. The model-cost tooltip lists the model lines, service lines and the total; the service-cost tooltip lists the service lines only. A snapshot's `service_only` flag decides whether an entry is folded away; without the flag, "has service items and no model charge" decides.
- web/settings billing | Charts and heatmap rendering. | Hand-written SVG (no chart library): stacked bars with a legend that toggles series, top-ten models plus "other", and a pure heatmap grid. Tooltips follow hover/focus of each column.
- web/settings billing | After a free plan switch the spec reloads the page. | The page reloads its own data, the activity grid, the usage log and the session user instead of a full document reload.
- web/settings billing | Payment return. | The success/cancel URLs are `<origin>/settings/subscription?payment=success|cancel`; the page shows a toast for the parameter and removes it from the address.
- web/settings account | QR codes for authenticator setup. | A small in-house encoder (byte mode, error correction M, versions 1 to 10, up to 213 bytes). Longer text falls back to the manual tab with an "unavailable" note.
- web/settings account | Linking another sign-in identity (bind). | Same PKCE bridge as sign-in: client id `riochat-web`, redirect `<origin>/auth/callback?provider=<slug>`, request stored under `riochat:oauth:<slug>:bridge` with intent `bind` and `next=/settings/account`, started with `POST /me/identities/providers/<slug>/authorize`. Desktop loopback delivery is not implemented here (a browser navigation is used).
- web/settings account | Password trimming. | The new password is validated and sent trimmed, as the policy states.
- web/settings tools | Where the default MCP selection is stored. | In the user setting `chat.default_mcp_tool_ids` as a JSON array of tool ids, capped by `GET /settings/mcp-policy` (`maxSelectedToolsPerMessage`). Ids of tools the administrator removed are dropped from the displayed selection.
- web/settings memory | The preference list is capped at 20 in the spec but the server allows 500 entries. | The chat page keeps the 20-item cap for the preference scope only; the memory page has no client cap and relies on the server's limit error.
- web/settings network | The desktop network component is "owned elsewhere". | A minimal page lets the desktop shell change the server address through `setApiBaseOverride`; in a browser the page redirects to General.
- web/settings about | The spec says no data is loaded. | The page reads `GET /version` (public) for version, commit and build time and shows dashes when it fails.
- web/auth | An existing session is found while `next` is missing or unsafe, before the login-page settings have loaded. | The redirect waits for the settings document (or its failure) so the server's `defaultNextPath` is honoured; a safe `next` redirects immediately without waiting.
- web/auth | `next` values containing control characters (tab, line feed, NUL). | Rejected like any other unsafe value, because URL parsers drop those characters and `/<tab>/host` would otherwise become a protocol-relative redirect. The same rule applies to links inside rendered Markdown.
- web/auth | The human-check widget cannot load (blocked script, offline). | An inline alert with a "Try again" button replaces the empty box; the Send and Create buttons stay disabled until a token exists.
- web/shell | Search caches across accounts. | The default-list cache and the preview cache are cleared as soon as the session token becomes empty (sign-out), so a second account in the same tab never sees the first one's conversations. A failed first page also clears the previous query's results instead of leaving them next to the error.
- web/announcements | Partial failure of "Close" / "Not again today". | Items the server accepted are marked read locally and only the failed ones are retried; the dialog still stays open with the failure toast. Sorting uses pressed buttons rather than tab roles (there is no tab panel).
- web/share | Snapshot messages with status `blocked`, `interrupted` or `canceled`. | The server blanks blocked content; the page shows a muted "not available in the shared copy" note (user and assistant) and a muted "did not finish" note for interrupted/cancelled replies instead of an empty bubble.
- web/recent | Stop-sharing across several 100-id chunks where a later chunk fails. | Rows whose chunk was accepted are shown as unshared (page and sidebar) before the error is reported in the dialog.
- web/onboarding | Focus after a step change. | The new step's heading receives focus (the activating button no longer exists), so keyboard and screen-reader users continue from the top of the new step.
- web/settings appearance | The spec cancels a pending appearance write when the page unmounts. | The pending write is sent immediately on unmount instead. The choice was already applied on this device, so dropping it would leave the account and the device disagreeing until the next change; the 300 ms debounce and the "nothing without a token" rule are unchanged.
- web/settings load errors | The spec only says "toast" for most failed loads, so a failed load looked like an empty page. | Pages that own a list or a form (chat, tools, skills, models, import, account, subscription, usage log) also show an inline alert with the localized reason and a "try again" button, and the controls that need the data stay disabled. The toast stays where the spec asks for one.
- web/settings usage log | "Changing search, filter, sort or page size resets to page 1" with "one request". | The page is remembered together with the filters it was chosen under, so the render that sees new filters already asks for page 1: a single request, never the old page with the new filters first.
- web/settings row actions | Providers, skills and notes can be changed while another row's request is still running. | Each result is applied to the list as it is when the request finishes, not to the list that was on screen when it started, so a slow request cannot bring back a row another request already changed or removed.
- web/settings loading flag | A list page flashed its empty state (and the import page cleared its stash) for one render between "access known" and "request started". | `useLoad` reports loading from the moment it is enabled until the request for the current key has settled.
- web/admin shell | The sidebar shows an update badge fed by the About page's release check. | Not wired into the shell. The About page keeps the cached release result and exposes it as an event only; the sidebar belongs to the shell area.
- web/admin lists | The spec mentions row virtualization above 100 rows. | Not built. Server pages are at most 100 rows and the MCP lists are paged at 25, so a plain table stays fast; the tool sheet shows its rows paged.
- web/admin logs cleanup | `/admin/logs/cleanup` is documented but not mounted by the backend yet (it appears only in the audit model notes). | The dialog and request follow the spec; until the route exists the server answers 404 and the failure toast shows the reason.
- web/admin settings secrets | The settings API clears a stored secret only with `clear: true`. | The console never sends `clear`; a blank secret field means "keep". Clearing a secret is therefore not possible from the UI, which avoids wiping a key by mistake.
- web/admin users personal providers | The spec updates the settings cache after a personal-provider access change. | The page dispatches the `riochat:personal-provider-access-changed` window event; whichever area owns the settings cache listens for it.
- web/admin bridge notice | Where the bridge-notice banner lives. | `AdminBridgeNotice` is mounted once in `app/admin/layout.tsx` so every admin screen shows it.
- web/admin identicons, markdown, sandbox | The clean-room rules forbid copying designs. | Avatars use our own identicon generator, Markdown previews use a small own subset parser (`mini-markdown.ts`), and component previews talk to the sandbox frame through our own `riochat:props` message.
- web/admin option policy | The spec describes the policy as lists of paths. | The page adds a live preview that evaluates sample paths against the current lists and mode, so a wrong rule is visible before saving.
- web/admin reordering | Drag-only reordering is not keyboard accessible. | Every sortable list has native drag plus up/down buttons on each row; saving sends the whole order in one request, only when something changed.
